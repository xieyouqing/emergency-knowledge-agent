# 应灾知识-离线应答库

面向**低知识水平人群**的离线灾害应急知识库。单文件 JSON，零网络依赖，可在断网状态下即时回答「煤气泄漏怎么办」这类问题。

## 文件

| 文件 | 用途 |
|---|---|
| `应灾知识-离线应答库.json` | 主库（v1.5.2，24 场景），Agent 直接加载 |
| `应灾知识-离线应答库.db` | SQLite 版，便于开发者 SQL 查询 |
| `应灾知识-离线应答库-README.md` | 本文件 |

## 设计原则

1. **离线可用**：单文件 JSON，加载 0.6 ms，不需要任何网络
2. **低知识水平**：每场景最多 3 步、每步 ≤ 18 字、动词开头、无专业术语（"剑突"→"胸口下方软的地方"）
3. **可审计**：每条步骤/禁忌都溯源到 `应灾知识-数据表.xlsx` 的行号与逐字原文
4. **安全优先**：不确定就兜底到 120/119，不让用户自己判断病情

## 匹配算法

**最长匹配优先（longest-match）**：多个场景命中同一个关键词时，取匹配关键词最长的那个。

```
"电动车着火了" → battery_fire（"电动车着火" 6字）> fire_escape（"着火" 2字）
"被海蜇蜇了"   → jellyfish（"海蜇" 2字）> bee_sting（不再含"蜇"）
```

Python 实现：
```python
def match(text, kb):
    best, best_len = None, 0
    for s in kb["scenes"]:
        for kw in s["keywords"] + s.get("question_variants", []):
            if kw in text and len(kw) > best_len:
                best, best_len = s, len(kw)
    return best
```

## 兜底规则

- **无匹配**：`"这个我还不会。请立刻拨打 120 或 119，说清楚你在哪、发生了什么，按接线员说的做。"`
- **有冲突**：`"有两个说法，不确定哪个对。安全起见请立刻拨打 120，按急救人员说的做。"`
- **任何场景**：如果出现昏迷、呼吸停止、心跳停止、大量出血、抽搐、意识不清 → 立刻 120

## 与源表的关系

本库从 `应灾知识-数据表.xlsx` 的 `1-官方文件` 表（280 行）派生：
- 只取**处置层**行（可执行步骤），不取法条/制度层
- 只取**公众可操作**的步骤，医务人员操作不进 steps
- **反面留档**行（蛇咬旧说、溺水 15:1）进入 `never_do` 列表
- 每条 `source_id` 可回查源表的「原文摘抄」和「来源名称」
- `meta.source_rows` 记录派生时的数据行数（280）；`meta.source_ids_sha1` 记录「编号」列去重排序后的 sha1，两者合起来做对账
- ⚠️ 原 `meta.source_md5` 已于 v1.5.2 移除：实测两版源表 md5（14:10 版 `98564d76…`、17.00 版 `14fde534…`）均不等于原声明值 `5082000c…`，该字段从未对账成功过（Office 重存与网盘导出都会改变字节）。行数 + 编号哈希不随重存变化

## 离线部署

把 `应灾知识-离线应答库.json` 放到设备上，App 启动时加载一次即可。不需要网络、不需要数据库驱动。

```python
import json
with open("应灾知识-离线应答库.json", encoding="utf-8") as f:
    kb = json.load(f)
# 之后所有查询都走内存
```
