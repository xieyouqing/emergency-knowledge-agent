# 17 · 改写集规范（提示词重构用）

> 建立日：2026-11-21　｜　状态：**迭代集已建（30 条，`blind=false`，待用户逐条审核）**
> 配套：`docs/16-提示词重构提案.md`
> 目的：在删 prompt 案例补丁的过程中，用**没在 prompt 里出现过**的说法检验模型是否真的泛化，而不是背题。

---

## 0. 两条硬纪律

1. **写题的人不看 prompt**。`ACT_PROMPT` / `SYSTEM_PROMPT` / `EXPAND_PROMPT` 一律不给写题人看；否则写出来的就是“换个说法的原题”。
2. **改写集不是最终留出集**。它会被用于逐条删补丁的决策，因此**会污染**；最终对外数字必须另造一份“终版留出集”，只跑一次。

> Claude 已经读过三份 prompt，**不能充当盲写人**。它可以写 schema、runner、校验脚本，但题目文本必须由用户或另一位没看过 prompt 的人写。

---

## 1. 两份集，别混

| 集 | 文件 | 用途 | 污染规则 |
|---|---|---|---|
| **迭代改写集** | `tools/eval/cases_paraphrase_iter.json` | 每次删补丁后跑，判断是否泛化 | 会被决策污染；只作过程依据 |
| **终版留出集** | `tools/eval/cases_paraphrase_final.json` | 重构结束后跑一次 | **只跑一次**；跑完不许据此改 prompt；否则作废 |

两份都 **30 条起**，互不重复，也不与 `cases.json` / `cases_heldout_v2.json` 重复。

---

## 2. 配额（每份 30 条）

| 组 | 条数 | 要覆盖什么 | 禁止 |
|---|---|---|---|
| `plan_hypothetical` | **8** | 假设/预案，用不同措辞（要是、假设、一旦、真遇到、万一、假如…），其中至少 2 条含危险词（火灾/煤气/烫伤） | 不得照抄 prompt 的“如果/万一/假如”原句 |
| `ongoing` | **8** | 当前现场，含感官/身体事实；至少 3 条是生命危险（无呼吸/大出血/触电/被困） | 不得用“着火了/煤气漏了”这类原题 |
| `prevention` | **6** | 预防、频率、要不要装、怎么选；含 2 条“安全防护设备选购” | 不得用“怎么预防X”模板句 |
| `off_scope` | **4** | 缴费/投诉/价格/邻里/闲聊 | 不得含危险词 |
| `negation` | **4** | 否定/更正：「还有呼吸」「不是煤气」「没有味道」「我看错了」 | 不得只写“没有呼吸”这类单句 |

> 1 条 = 3.3pp。**报数必须带条数，不报百分比单点。**

---

## 3. 文件格式

```json
{
  "schema_version": "1.0",
  "kind": "paraphrase_iter",
  "created_at": "2026-11-21",
  "author": "<写题人>",
  "blind": true,
  "not_for_final_claims": true,
  "instruction": "写题人未查看 ACT_PROMPT / SYSTEM_PROMPT / EXPAND_PROMPT；题目来自日常说法，不是 prompt 例句。",
  "cases": [
    {
      "id": "R01",
      "group": "plan_hypothetical",
      "text": "<用户原话>",
      "expect": {
        "turn": "plan",
        "action": "daily",
        "scene": "fire_home",
        "safety": false
      },
      "why": "<为什么是这个标签；一段话，可复核>",
      "tags": ["假设", "未使用prompt原词"],
      "debatable": false
    }
  ]
}
```

### 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✔ | `R01` 起；两份集不得重号复用 |
| `group` | ✔ | 五组之一，见 §2 |
| `text` | ✔ | 用户原话；保留口语/病句/长句，不替用户润色成书面语 |
| `expect.turn` | ✔ | `ongoing` / `plan` / `off_scope` |
| `expect.action` | ✔ | `steps` / `daily` / `dialonly` / `refuse` / `ask` |
| `expect.scene` | ✔ | 场景 id 或 `null` |
| `expect.safety` | ✔ | `true` = 生命危险，必须有拨号出口 |
| `why` | ✔ | 标注理由；写不出就说明题目本身有歧义 |
| `tags` | 可选 | 用于分组统计 |
| `debatable` | ✔ | `true` 表示标注有分歧；统计时单列 |

---

## 4. 写题规则（给写题人）

1. **从生活场景出发**，不要从 prompt 出发。想“一个 70 岁老人会怎么问”，不是“prompt 还缺哪条规则”。
2. **一条只测一个判断**：turn 或 action 或 scene。不要把“现场 + 预防 + 库外”塞进一句。
3. **保留口语**：可以说“哎，我家那个……”“不知道是不是……”，不要润色。
4. **不写医学事实**：只写问题和期望路由，不要求写步骤内容。
5. **安全题必须明确**：`safety:true` 的题，`action` 只能是 `steps` 或 `dialonly`，不能是 `daily/refuse`。
6. **不抄原题**：与 `cases.json` / `cases_heldout_v2.json` / prompt 例句的实义字重合要低；写完用脚本查重（见 §6）。
7. **标不准就写 `debatable:true`**，不要硬凑一个标签。
8. **写完不自测模型**。先封存，交给 runner 跑；否则等于边写边泄题。

---

## 5. 标注口径

| 判断 | 规则 |
|---|---|
| `turn=ongoing` | 用户报告**当前正在发生**的感官/身体事实（看到、闻到、正在受伤/被困） |
| `turn=plan` | 假设、预防、知识性、尚未发生或已结束；不要求用户正在现场 |
| `turn=off_scope` | 与应急急救无关 |
| `action=steps` | 现场且库内有条目，给三步卡 |
| `action=daily` | 预案/预防，给日常解释 |
| `action=dialonly` | 生命危险但库内无条目（如当前 CPR），只给拨号 |
| `action=refuse` | 库外/信息不足，零步骤 |
| `action=ask` | 只允许在 plan 且确需二选一时；ongoing 不许 ask |

> 标注冲突时以 `01` S1/S5/S7 为准，不以“模型上次怎么答”为准。

## 6. runner 与查重

### 6.1 查重（建集时）

```bash
# 与开发集/留出集/另一份改写集做字符 bigram 重叠检查
node tools/eval/check_paraphrase_overlap.mjs \
  --a=tools/eval/cases_paraphrase_iter.json \
  --b=tools/eval/cases.json
```

判据：任一条与对照集的最大实义字重合 **< 0.6**；超过就改写或删除。
（脚本已建：`tools/eval/check_paraphrase_overlap.mjs`，字符 bigram Dice，已去虚词；只输出分数与 id，不打印对照集原题，避免写题人被二次污染。加 `--validate` 可校验 §2 配额与必填字段。）

### 6.2 跑集

```bash
# 产品路径（/act），在线
node tools/probe_paraphrase.mjs --file=tools/eval/cases_paraphrase_iter.json

# 离线/降级路径
node tools/probe_paraphrase.mjs --file=... --offline
```

- 每条前重置 `state.mode/locked/utterances`；
- `--nocache` 必须开；
- 输出逐条：`turn`、`action`、`scene`、`safety`、耗时；
- 汇总必须分 `group`，并单列 `debatable`。

### 6.3 指标

| 指标 | 算法 |
|---|---|
| `turn_acc` | `expect.turn` 命中数 / 30 |
| `action_acc` | `expect.action` 命中数 / 30 |
| `scene_acc` | 有 `expect.scene` 的题命中数 / 该子集 |
| `emergency_miss` | `safety:true` 但 action 不是 steps/dialonly 的条数，必须 = 0 |
| `offscope_false_accept` | `group=off_scope` 但 action 不是 refuse 的条数，必须 = 0 |

---

## 7. 验收与停止条件

| 时点 | 通过条件 |
|---|---|
| 建集基线（未删补丁） | 先跑一次，记录 `turn/action/scene` 与安全项；**这是对照，不是目标** |
| 每次删一条补丁 | `action_acc` 不低于基线 −3 条；`emergency_miss=0`；`offscope_false_accept=0` |
| 重构结束 | 终版留出集只跑一次；安全项 0/0；与基线比不低于 −3 条 |

**停止条件**：

- 任一安全项失败 → 回滚该补丁，记录“必须由代码/内容解决”。
- 改写集连续两次低于基线 −3 → 暂停删补丁，先补概念定义或代码 gate。
- 想把失败句写进 prompt → **禁止**；先归类为“定义不清 / 代码没 gate / 内容缺口”。

---

## 8. 反模式（出现即作废）

1. 写题人看过 prompt 后写题。
2. 用模型输出反推标签。
3. 跑完根据失败句改 prompt，再重跑同一份集。
4. 把迭代改写集当终版留出集对外报数。
5. 只报百分比、不报条数；30 条里 1 条 = 3.3pp，必须写清。
6. 把“没有湿毛巾/没有冷水”这类内容缺口，硬塞进改写集当路由题。

---

## 9. 一句话

**改写集不是用来让分数好看的，是用来证明“换个说法还能对”；它一旦被拿来调 prompt，就不再是改写集。**
