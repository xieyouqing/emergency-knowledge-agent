# 16 · 提示词重构提案（去案例补丁 → turn_type 契约）

> 建立日：2026-11-21　｜　状态：**Phase 1 已实现；Phase 3 的 ACT 瘦身 + SYSTEM 定义化已完成；EXPAND 动词枚举未删**。当前 `/act` 100/100、`/judge` 97/100、安全项 0/40、0/30。
> 触发：用户指出「往提示词里打补丁像机器预习了」。本提案只做一件事：**把案例补丁从 prompt 里拿掉，换成「语义标签 + 代码策略」。**
> **不是删安全契约**：S1/S5/S7/S10/S11、工具前置条件、输出 schema 全部保留。

---

## 0. 结论

**同意重构，但必须分阶段，不能一把删。**

- 案例补丁（“如果/万一…”“开灯/按门铃…”“选购两张清单”“ack 的具体例子”）→ 删除或迁移。
- 安全契约（不编步骤、生命危险拨号、动作只来自条目、来源 pass、人签）→ 保留。
- 新规则不是“再写一批案例”，而是：模型输出 `turn_type` + 证据，代码按类型限制工具。
- 验收必须用**未参与调参的改写集**，否则删补丁后开发集掉分会被误判成“变差”。

## 3. 新契约：`turn_type` + 证据

### 3.1 模型输出

`/act` 与 `/judge` 的 JSON 增加两个字段：

```json
{
  "turn": "ongoing|plan|off_scope",
  "evidence": "<用户哪句话说明是现场/预案；一句话，不得为空>",
  "act": "...",
  "args": {...},
  "reason": "...",
  "note": ""
}
```

**定义（不举例）**：

- `ongoing`：用户报告**当前正在发生**的感官或身体事实（看到、闻到、正在发生的伤害/危险）。
- `plan`：用户用假设、预防、知识性语气描述**尚未发生或已结束**的事（“如果/万一/怎么预防/平时/能不能”）。
- `off_scope`：与应急急救无关。

> 注意：定义里可以出现“如果/怎么预防”，但**不再列具体短语清单**，也不把测试句写进 prompt。

### 3.2 代码策略

| `turn` | 允许工具 |
|---|---|
| `ongoing` | `lookup_scene, get_steps, triage, dial, speak, refuse, ack` |
| `plan` | `lookup_scene, get_daily, speak, refuse, ask` |
| `off_scope` | `refuse` |

- 模型仍在允许集合内**自主选工具**；代码只做 gate。
- `turn=plan` 时若模型仍选 `get_steps/triage/dial` → 同场景有条目则降级 `get_daily`，否则 `refuse`。
- `turn=ongoing` 时 `ask` 仍禁用（现有规则 6 的安全契约保留）。
- 回合继承：上一轮 `plan`、当前句只是补充条件且无新现场信号 → 继承 `plan`（代码判断，不靠 prompt 举例）。

### 3.3 安全契约不动

- S1：不编步骤；库外零步骤。
- S5：生命危险条目必须有拨号按钮 + 播报“同时拨打 N”。
- S7：日常动作只能来自条目字段。
- S10/S11：来源机器 pass + 人工签步骤顺序。
- 工具前置条件（`lookup_scene` 先于内容工具）。

## 4. 分阶段执行

### Phase 0：冻结与快照

- 从现在起不再往 prompt 加案例；所有新问题先归类为“概念/代码/内容”。
- 快照当前 `ACT_PROMPT`/`SYSTEM_PROMPT`/`EXPAND_PROMPT` 与基线数字。

### Phase 1：加 `turn_type`（additive，不删旧补丁）

- `/act`、`/judge` 输出增加 `turn/evidence`。
- 代码 gate 使用 `turn`；旧 prompt 规则暂留。
- 跑 100/12/28/P5，确认不回归。

### Phase 2：建改写集（不调参）

> 完整规范见 `docs/17-改写集规范.md`：两份集（迭代/终版）、30 条配额、字段、写作规则、查重、runner、停止条件。

- 30 条“没在 prompt 里出现过”的说法，覆盖：
  - 假设/预案 8 条（不同措辞，不用“如果/万一”原词）
  - 现场 8 条（含模糊表述）
  - 预防/选购 6 条
  - 无关 4 条
  - 否定/更正 4 条
- 规则：**写集的人不看 prompt；跑完不据此改 prompt**，只用来判“是否泛化”。

### Phase 3：逐条删补丁

按风险从低到高：

1. 删 `SYSTEM_PROMPT` / `ACT_PROMPT` 的选购清单（保留原则）。
2. 删 `ACT_PROMPT` 规则 2 的假设词表与现场征兆枚举（交给 `turn`）。
3. 删规则 5 的“不是他/孩子”举例（P32 已代码处理）。
4. 删规则 8 的“不是煤气/油烟”举例（更正交给 `turn=off_scope` / 内容）。
5. 删 `note` 示例句（保留约束）。
6. 删 `EXPAND_PROMPT` 的动词枚举（`p5_core` 已 gate）。

每删一条：跑 100 + 12 + 28 + P5 + 改写集；任一安全项（emergency 40/40、off_scope 0/30）掉 → 回滚该条并记录原因。

### Phase 4：新留出集与收口

- v2 已污染；另造一版 42+ 条**未参与调参**的留出集，最终只跑一次。
- `turnPolicy` regex 是否保留为兜底：看离线/代理不可用场景。

## 5. 验收与停止条件

| 阶段 | 通过条件 |
|---|---|
| Phase 1 | 100 条 action ≥ 当前（99/100）；安全项 40/40、0/30；12/12；P5 ≥26/27 |
| Phase 3 每条 | 同上 + 改写集不低于基线 −3 条；无新增安全失败 |
| Phase 4 | 新留出集 ≥ 当前留出集（同口径）；安全项 0 漏给 / 0 误纳 |

**停止条件**：

- 删除某条补丁后，安全项掉 → 立即回滚，标注“该行为必须由代码/内容解决，不许回 prompt”。
- 改写集连续两次低于基线 −3 → 暂停 Phase 3，先补概念定义或代码 gate。

## 6. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 开发集掉分 | 补丁在开发集上过拟合；删了会掉 | 以改写集/新留出集为准，不因开发集掉分回滚 |
| `turn` 本身变成新补丁 | 如果定义又写成案例清单 | 定义只写概念；`evidence` 用来审计，不写测试句 |
| 模型不输出 `turn` | 结构不合法 | 代理侧校验；缺失则回落本地 `turnPolicy` |
| 延迟 | 同一调用多输出两个字段，不增加往返 | 实测 P50；若 token 增长影响首字，再评估 |
| 内容缺口被误当路由问题 | 如“没有湿毛巾/没有冷水” | 先判内容/来源；不往 prompt 加案例 |

## 9. 一句话

**补丁能过今天的测试，过不了明天的说法。** 把“怎么说”交给模型（`turn` + 证据），把“能不能做”交给代码（工具 gate），把“有没有内容”交给数据（来源）；prompt 只保留契约，不再收藏案例。
