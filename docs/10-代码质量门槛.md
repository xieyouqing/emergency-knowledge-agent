# 10 · 代码质量门槛

> 建立日：2026-11-19　适用：`app/`（前端手写代码）
> 本文件只写「怎么卡」，不写「怎么写业务」。业务契约见 `02-数据契约.md`。

---

## 1. 结论先行

三样能力必须用三套不同机制保障，混在一起谈必然落空：

| 能力 | 靠什么 | 能不能自动判 |
|---|---|---|
| 规范性 | ESLint 语义规则（错误类） | 能，退出码 |
| 可读性 | 行数/嵌套阈值 + 文件头契约 | 行数能数，嵌套目前靠人看 |
| 可拓展性 | 依赖方向 + 加载顺序 + 入口唯一 | 部分能（缺失即 throw） |

**核心判断：可读性不能靠「清晰」「易读」这类词来验收，必须换成可数的东西。**
所以本文件里所有阈值都写成数字，所有判据都写成「一个动作 + 一个可观察结果」。

## 2. 怎么跑

```bash
npm install          # 首次，装 prettier / eslint（devDependencies，不进产物）
npm run verify       # = fmt:check + lint，提交前必须全绿
```

| 命令 | 期望输出 | 什么情况算不过 |
|---|---|---|
| `npm run fmt:check` | `All matched files use Prettier code style!` | 退出码 1，并列出具体文件 |
| `npm run lint` | 无输出 | 退出码 1，列出 `文件:行:列  规则名` |
| `npm run fmt` | 就地格式化 | —（只对新文件用；旧文件见 §4） |

**退出码必须直接取，不能被管道吃掉。** 正确写法：

```bash
npx eslint app/ ; echo "exit=$?"
```

反例：`npx eslint app/ | tail -5; echo $?` —— `$?` 取的是 `tail` 的退出码，恒为 0。
本文件的全部「通过」结论都是按前一种写法取到的。

## 3. ESLint：只开能明确判对错的规则

配置文件：`eslint.config.mjs`（flat config，ESLint 9.39）

| 规则 | 抓什么 | 为什么开 |
|---|---|---|
| `no-undef` | 用了未声明的变量 | 跨文件靠 `window.*` 挂载，拼错名字不会报错，只会静默失效 |
| `no-unused-vars` | 声明了没用 | 残留变量是「改到一半」的信号 |
| `no-implicit-globals` | 漏写 `var` 导致的全局泄漏 | 7 个 `<script>` 共享全局作用域，一次泄漏可能被别的文件读到 |
| `eqeqeq`（`null: 'ignore'`） | `==` 比较 | `==` 的隐式转换是静默 bug 源头 |
| `prefer-const` | 该用 const 却用 let | 现在全是 `var`，此规则暂不生效；将来写 `let` 时自动生效 |

**`null: 'ignore'` 是必须的，不是放水。** 实测 4 处 `==`（`app.js:444`、`log.js:61/77/290`）
全部是 `x == null`——这是同时判 `null` 和 `undefined` 的惯用写法。
改成 `=== null` 会让 `undefined` 漏判，**属于行为变更**。
所以正确做法是配规则，不是改代码。

**不开的规则**：风格类全部不进 ESLint（交给 Prettier）。
`no-var` 不开——全库 ES5 写法是刻意选择，开了等于要求重写 4000 行。

### 3.1 ecmaVersion 为什么是 2022 而不是 5

实测推翻了「纯 ES5」的判断：

- **语法**层：确实是 ES5（`var` + IIFE + 回调，无 `let`/`const`/`async`/`=>`）
- **运行时 API**层：用了 `Promise`、`globalThis`、`Float32Array`、`AudioContext`，均属 ES2015+

把 `ecmaVersion` 定成 5，ESLint 会认为 `Promise` 这些全局对象不存在，
首跑报 33 条假 `no-undef`。定 2022 后降到 5 条真问题。

**由此得出一条该写进认知的事实：ES5 是风格选择，不是兼容性保证。**
用了 `Promise` 就已经排除了不支持 ES6 的浏览器，真正决定兼容边界的是用到的 API，
不是缩进和 `var`。

## 4. Prettier：增量接管，不回溯

配置：`.prettierrc`，忽略名单：`.prettierignore`

关键配置项及理由：

| 项 | 值 | 理由 |
|---|---|---|
| `trailingComma` | `es5` | 默认 `all` 会给**函数参数**补尾逗号，那是 ES2017 语法，直接破坏兼容 |
| `singleQuote` | `true` | 与现有代码一致 |
| `printWidth` | `100` | 实测 80/100/120 三档全量重排分别为 2239/1919/1759 行，差距不大，取中间值 |
| `endOfLine` | `lf` | 仓库内行尾混乱（`app.js` 是 CRLF，其余 LF），统一到 LF |

### 4.1 为什么不全量重排（这是本次唯一的取舍）

**实测：现有 8 个手写文件全量重排会改动 1919 行（行尾归一后），约占总行数的 43%。**

且这不只是「宽度不同」，Prettier 会拆掉有意为之的排版：

```
现有:      var buffer = [];          // 环形缓冲（最近的日志，供界面/自测读取）
           var pending = [];         // 待发送
           var dropped = 0;          // 因缓冲满被丢弃的条数

Prettier:  var buffer = []; // 环形缓冲...
           var pending = []; // 待发送
           var dropped = 0; // 因缓冲满被丢弃的条数
```

对齐的尾注释放量：`asr.js` 16 处、`style.css` 6 处、`log.js` 4 处、`app.js` 2 处。
另有短函数体被强制折行（`llm.js:70`、`log.js:82`）也会被合并成一行。

**结论：全量重排会以「可读性」之名降低可读性，故不采纳。**

采用增量接管 —— 边界是**时间**，不是**文件好坏**（后者说不清）：
`.prettierignore` 中列出的 8 个文件不纳入检查，本文件创建日之后的新文件自动纳入。

### 4.2 迁移触发条件（不许无限期挂着）

某文件因功能改动需要大面积重排时，**单独一次 commit 只做格式化**：
删掉 `.prettierignore` 里对应的一行，commit message 写明「仅格式化」。
混在功能改动里提交，等于让 review 失效。

## 6. 已知缺口（必须写明，不许藏）

| 缺口 | 实测数据 | 风险 | 处理 |
|---|---|---|---|
| Prettier 对既有文件覆盖率为 **0** | 8 个文件全在忽略名单 | 低（是渐进棘轮，非空转：新文件自动覆盖） | 按 §4.2 逐个迁移 |
| 单文件行数超 400 | `app.js` 850 行、`knowledge.js` 1234 行 | 中 | `knowledge.js` 是生成物，豁免；`app.js` 拆分属模块划分，需提案 |
| 单函数 ≤50 行、嵌套 ≤3 层无法自动检查 | 无工具 | 中 | 待引入复杂度检查，见待办 |
| 无单元测试 | 仓库内无测试文件 | 中 | 目前靠 `09-M1-自测记录.md` 人工回归 |
| 行尾混乱 | `app.js` CRLF，其余 LF | 低 | 已在 `.prettierrc` 定 LF；旧文件迁移时顺带修正 |

### 可拓展性的三条约束（当前状态）

1. **横切模块必须可摘除。** 范式是 `app/log.js`：`window.LOG` 不存在时全 no-op，
   产品行为不变。新增埋点/缓存/超时必须照此写，否则它就没法被单独测试或替换。
2. **不能依赖 `index.html` 里的 script 顺序。** 目前 7 个 `<script>` 的先后就是隐式契约。
   只有 `app.js` 对 `RETRIEVAL` 缺失做了 `throw`，其余文件没有 —— 顺序写错会静默降级。
3. **加引擎是加一层，不是改旧层。** `retrieval.js` 从 `app.js` 迁出就是正例：
   三层引擎必须能被同一份 100 条评测集无差别调用，否则「测的」与「用的」是两套实现。
