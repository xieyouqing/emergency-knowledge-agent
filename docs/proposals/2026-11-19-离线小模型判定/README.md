## 这份文件夹是什么

回答一个问题：**断网时怎么判断用户说的是什么事**。现有实现只有字符匹配，实测 prevention 只判对 3/30。本提案给出「内置一个小模型」的完整证据链。

| 文件 | 内容 | 什么时候读 |
|---|---|---|
| `01-提案.md` | 背景、结论、架构、被否决的方案 | 要决策时读 |
| `02-实现方案.md` | 具体怎么改、改哪几个文件、判据、回退、工时 | 动手前读 |
| `03-数据支持.md` | 全部实测数字（含失败轮次） | 被质疑数据时读 |
| `04-验证结果.md` | 复现命令、原始输出、未验证项 | 要自己复跑时读 |

| `data/汇总.json` | 关键数字的机器可读版本 | 写 PPT 取数时用 |

## 一页速览

| 项 | 规则基线（现在） | 本提案 | 差 |
|---|---|---|---|
| 意图三分类（100 条） | 61% | **85%** | +24 |
| 紧急召回（40 条） | 40/40 | **40/40** | **0（不退化）** |
| 预防判对（30 条） | 3/30 | **25/30** | +22 |
| 无关问题判对（30 条） | 18/30 | 20/30 | +2 |
| 场景定位（70 条） | 77.1%（14 条零命中） | **92.9%** | +11 条 |
| 体积成本 | 0 | **22.9 MiB** | — |
| 单句耗时 | ~0 | **21 ms（p50）** | 3 秒预算的 1% |

**核心结论**：模型不能单独用——单独用会把紧急召回从 40/40 拉到 30/40。必须「规则兜底 + 模型判意图/场景」组合，组合后紧急召回不退化、总体 +24 点。
