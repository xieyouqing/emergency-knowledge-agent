## 1. 总体思路：原型在构建期算好，运行期只算用户那一句

朴素做法是启动时把 3×8 条意图原型 + 10 条场景原型都嵌入一遍（28 次前向），实测单句 21ms，合计约 0.6 秒，纯属浪费——**这些原型在知识库不变时永远不变**。

因此：

```
构建期（Python，改知识库时才跑）
  knowledge/*.json + data/intent_protos.json
      → app/intent_protos.js      （预计算好的向量，约 35KB）

运行期（浏览器）
  加载模型（懒加载）→ 只嵌入用户那一句 → 与预存向量做点积
```

**收益**：运行期只有 1 次前向（21ms），而不是 29 次。首屏不受影响。

## 3. 运行期接口（`app/intent.js`）

```js
window.INTENT = {
  // 是否已完成加载并可用。首屏为 false，不阻塞任何现有路径。
  ready: function () { return _ready; },

  // 唯一对外方法。同步，模型未就绪时返回 null（调用方自行退回规则）
  classify: function (text) {
    // 返回:
    // {
    //   intent: 'ongoing' | 'prevention' | 'off_scope',
    //   scene:  'gas_leak' | ... | null,     // 低分时为 null
    //   margin: 0.031,                       // top1 - top2
    //   scores: { ongoing: 0.52, prevention: 0.55, off_scope: 0.31 },
    //   overridden: true,                    // 是否被规则兜底改写
    //   candidates: ['gas_leak', 'fall_elderly']  // 多命中时给 L2 用
    // }
  },

  // 懒加载入口，由 app.js 在首屏渲染完成后调用
  load: function () { return _promise; }
};
```

**硬约束**：`classify()` 必须是纯函数语义——不写 DOM、不动 `state`、不调 `LOG` 以外的东西。这样它能被 `selftest_intent.mjs` 直接跑。

## 4. 判定逻辑（与探针 V3 逐行一致）

```js
function classify(text) {
  var ruleHits = RETRIEVAL.detectDanger(text);        // 数组，改动 #7
  var v = embed(text);                                 // 21ms
  var s = dot(v, PROTO.intentCentroids);               // 3 次点积
  var top = argmax(s), margin = s[top] - second(s);

  var pred = top;

  // 兜底：规则命中 且 模型没判紧急 且 模型拿不准 → 按紧急处理
  var overridden = false;
  if (ruleHits.length && pred !== 'ongoing' && margin < MARGIN) {
    pred = 'ongoing';
    overridden = true;
  }

  // 场景：取最高分，低于阈值给 null（交图标候选，不猜）
  var sceneTop = argmaxScene(v);
  var scene = sceneTop.score >= SCENE_TAU ? sceneTop.id : null;
  var candidates = sceneHits(ruleHits, sceneTop);      // 多命中 → 候选列表

  return { intent: pred, scene: scene, margin: margin, scores: s,
           overridden: overridden, candidates: candidates };
}
```

三个常量：

| 常量 | 值 | 来历 |
|---|---|---|
| `MARGIN` | 0.045 | 实测「emergency 恰好回到 40/40」的最小阈值（见 `03` §2.4）；**P-2 裁决前视为待标定** |
| `SCENE_TAU` | 待标定 | 场景定位 65/70，但未做阈值扫描；**实现时必须先跑一次扫描再定值**，不许沿用 intent 的阈值 |
| `SCENE_N` | 2 | 候选列表最多列几个（老人一次看不了更多） |

## 5. 接入点（`app/agent.js`）

现有优先级（`03` §2.5.9 已修正过一次，此处沿用，不许再改）：

```
有 LLM 判定结论（opts.plan） → 以 LLM 为准，模型/规则都不得覆盖
无模型结论 + 现在：detectDanger 命中 → 关键词先判
无模型结论 + 新增：INTENT.ready() → 用 classify()，规则作为兜底修正
无模型结论 + 未就绪/加载失败 → 退回现有字符规则（一字不改）
```

改动只在第二、三行之间插入一层，**在线链路一行不动**。这也意味着：**即使本提案实现有 bug，只要 `INTENT.ready()` 返回 false，系统行为与现在完全一致**——这是回退能力的来源。

## 7. 回退开关

```js
// app/state.js 加一个字段，默认跟随可用性
STATE.intentEngine = 'auto';   // 'auto' | 'rules' | 'model'
```

- `rules`：完全走现有字符规则，用于线上异常时一键降级
- `auto`：`INTENT.ready()` 为真用模型，否则规则
- 默认 `auto`，**判据 I1–I9 全过之后**才把默认值落盘
