## 1. 结论先行

模型与语音三块通道的**可切换性严重不对称**，这是当前最明显的架构债：

| 通道 | 可切换 | 靠什么切 | 成熟度 | 置信度 |
|---|---|---|---|---|
| 语音输入 ASR | ✅ 是 | `.env` 改一个变量，前端零改动 | 完整 provider 层 | 9 成 |
| 模型 LLM | ⚠️ 半 | 改 env 换 OpenAI 兼容厂商 | 无 provider 层，协议写死 | 8 成 |
| 语音输出 TTS | ❌ 否 | 改源码 | 两路硬编码分发 | 9 成 |

**核心判断：三块都是「外部服务」，抽象级别却差了两级。** ASR 已经是注册表模式，
LLM 和 TTS 还是 if/else。这个不对称不是设计选择，是演进顺序留下的。

## 2. 实测证据（可复核）

### 2.1 ASR：已做到

```
tools/asr/index.mjs    62 行  注册表 + pickProvider(env) + listProviders(env)
tools/asr/deepseek.mjs 81 行
tools/asr/xfyun.mjs   219 行  真实实现（hmac-sha256 签名、四个坑的处理）
```

切换方式：`.env` 里写 `ASR_PROVIDER=deepseek` 或 `ASR_PROVIDER=xfyun`。
前端 `app/asr.js` 只 POST 到 `/asr`，不知道后面是谁——**这是正确的分层**。

两个设计细节应保留，不要「优化」掉：

1. **默认值写死 `deepseek`**（`index.mjs:26`）。抽取接口不改变默认行为，否则
   `04 验收清单` 里所有基于 DeepSeek 的结论都要重跑，而没人记得为什么。
2. **provider 名拼错必须报错，不许静默回落**（`index.mjs:40`）。
   写 `xunfei`（少个 y）时若悄悄用 deepseek，你会以为测过了讯飞，
   实际测的是另一家——结论对不上还查不出来。

**残留缺陷**：`app/asr.js:38` 的 `ENDPOINT` 是模块级变量，
导出对象里 `config: { ENDPOINT }` 只是**值的快照**（`asr.js:367`），
改它不影响内部变量。换代理端口/域名仍需改源码。
对照：`llm.js` 有 `configure(opts)`（`llm.js:57`），`asr.js` 没有。

### 2.2 LLM：半可切换

可换：`DEEPSEEK_MODEL`、`DEEPSEEK_BASE_URL`（`llm_proxy.mjs:147-148`）走 env。
换 DeepSeek 自家模型，或任何 OpenAI 兼容厂商（通义、月之暗面、vLLM 自建），改 `.env` 即可。

**不能换的两层耦合：**

**① 协议耦合。** `llm_proxy.mjs:302` 用了 `response_format: { type: 'json_object' }`。
这是 OpenAI 兼容特性，部分厂商不实现。换成 Anthropic messages API 或 Gemini 原生协议，
`judge()` 函数体（`llm_proxy.mjs:288-356`，约 68 行）要重写。

**② 更要紧的：阈值是按 DeepSeek 标定的。**
`llm.js:32` 的 `MIN_CONFIDENCE = 0.60` 有明确依据：

> 100 条评测集上 confidence 分布 min=0.55 / P05=0.75 / P50=0.95；
> 扫描 T=0.50→0.90：T=0.60 时库外误纳率 96.7% → 100%，综合准确率 98.0% → 97.0%

换模型后**代码能切，这个数字作废**。新模型的 confidence 分布不同，
0.60 对它偏松还是偏紧完全未知。**必须重跑 100 条评测集重新标定**，
否则 S1「不许编」这条安全项就没有保障。

这不是代码问题，是验收问题。**结论：模型可换，但换完不重跑基线 = 没验证。**

### 2.3 TTS：没做到

`app/voice.js:307`：

```js
var p = state.engine === 'tauri' ? speakTauri(t, o) : speakWeb(t, o);
```

两路三元表达式。`stop()` 同样硬编码（`voice.js:385`）。`detect()` 也是
`if (isTauri()) {...}` 的固定顺序（`voice.js:84-107`）。
加第三路（云 TTS）要同时改 `speak`、`stop`、`detect` 三处，不是加一个文件。

**已确认的两个真缺陷（本节最关键，与提案选项无关，无论如何都要修）：**

**缺陷 1：`__TTsProbe` 有读无写。**
`detectTauriPlugin()` 读 `global.__TTsProbe`（`voice.js:108`），
但全仓库 grep 只有这一处**读**，没有任何地方**写**。
而 `setTauriAdapter(speakFn, stopFn)`（`voice.js:419-422`）只写 `__TTsSpeak`
和 `__TTsStop`，**不写 `__TTsProbe`**。

后果：宿主正确调了 `setTauriAdapter` 注入真实 TTS 实现，`detect()` 仍判不出
tauri 可用 → `engine` 停在 `'web'` → `speakTauri`（`voice.js:322`）**永远不会被调用**。
M3 打包后语音会静默落在浏览器层，而 Android 浏览器**没有 speechSynthesis**
（`docs/03` §2.4 事实 4）→ 最终落到 `engine: 'none'`，老人没有语音。

**缺陷 2：注释指向不存在的代码。**
`voice.js:324` 写「真实实现由宿主注入（见 index.html 末尾的适配片段）」。
实测 `grep -n "__TTs\|tauri" app/index.html` → **零匹配**，该片段不存在。
这属于文档谎报，会误导下一个人去 index.html 里找不存在的代码。

## 3. 三个选项

### 选项 A：补 TTS 的 provider 化 + 修两个缺陷

**改哪些文件**

| 文件 | 改什么 | 行数量级 |
|---|---|---|
| `app/voice.js` | ① 新增 provider 注册表（tauri / web 两个现成实现搬家）<br>② `speak()` / `stop()` / `detect()` 改查表分发<br>③ `setTauriAdapter` 补写 `__TTsProbe`<br>④ 删掉指向 index.html 的假注释 | 约 60 行改动 |
| `app/index.html` | 无（缺陷 2 是删注释，不是补代码） | 0 |

**关键实现约束（不遵守会破坏已验行为）**

1. 只做**内部分发收口**，不做跨文件抽象——`voice.js` 保持单文件，不新增 `voice/` 目录。
   理由：M3 打包时 `frontendDist` 就是 `app/`，file:// 直开不能有构建步骤，
   拆目录会增加路径管理的失败面。
2. provider 接口只定三个方法：`probe()` / `speak(text, opts)` / `stop()`。
   不要提前抽 `pause` / `resume`——产品没有这个需求，空接口是负债。
3. `detect()` 的**优先级顺序必须保持 tauri → web → none**，
   这是 `docs/01 §2.1` 定的（原生引擎音质与稳定性最好）。
4. 修 `__TTsProbe` 时改 `setTauriAdapter` 的签名会波及调用方——
   **不要改签名**，在函数内部根据 `speakFn` 是否存在推导 probe 结果即可。

**验证（每条都能失败）**

```bash
# 1. 静态门槛不退化
npx eslint app/ ; echo "exit=$?"        # 期望 0
npx prettier --check app/ ; echo "exit=$?"  # 期望 0

# 2. 已验朗读行为不退化（关键，这是主要风险）
node tools/e2e_voice.mjs                # 期望 16 条全过，一条不能少

# 3. 新增缺陷回归（必须先红后绿，证明断言有效）
node tools/e2e_voice.mjs                # 断言应含「注入 adapter 后 engine===tauri」
#    投毒：把 setTauriAdapter 里写 __TTsProbe 那行删掉 → 该条必须 FAIL

# 4. 全量自测
node tools/selftest_m1.mjs              # 期望 623 条全过（v1.1 执行后的基线；v1.0 写的 522 已过时）
```

**代价**

- 干活时间：约 1 小时（含跑测试）
- **主要风险：动的是 M2 已验收路径。** `e2e_voice` 16 条 + `selftest` 522 条必须全过，
  且要按 CODEBUDDY §7 做投毒反证，否则「全绿」不算通过
- 不解决 LLM 的可切换性

### 选项 B：A 的全部 + LLM 也 provider 化

**改哪些文件**

| 文件 | 改什么 |
|---|---|
| `app/voice.js` | 同 A |
| `tools/llm_proxy.mjs` | 抽出 `tools/llm/` 目录，比照 `tools/asr/`：<br>`index.mjs` 注册表 + `deepseek.mjs`（现实现搬家）<br>`judge()` 保留在代理层，只把「调上游」这一段交出去 |
| `app/llm.js` | 无（前端只认 `/judge`，与 provider 无关，**这点已经对了**） |

**必须额外做的事**

1. `MIN_CONFIDENCE` 的标定依据（`llm.js:32` 那段注释）**必须加一句**
   「本值仅对 DeepSeek 标定，换 provider 需重跑 docs/03 §6 评测集重新扫描」。
   不做这件事，下一个人换完 provider 会直接沿用 0.60。
2. 跑 100 条评测集确认基线不变：
   ```bash
   node tools/eval/run_eval.mjs --engine=llm    # 100 条准确率评测
   ```
   > **v1.1 修正**：v1.0 这里写的是 `node tools/e2e_llm.mjs --engine=llm`，**该参数不存在**。
   > `e2e_llm.mjs` 不读 `argv`，`--engine` 属于 `run_eval.mjs`。照抄会「命令跑通了但测的不是那件事」：
   > `e2e_llm` 是 46 条**链路**断言（输入→判定→路由→渲染），不是 100 条**准确率**。
   > 两个数字不能互相替代。
   **注意：这个数字会漂。** 2026-11-19 实测 97→96，原因是
   `DEEPSEEK_MODEL` 是浮动别名，服务端模型变了。所以「结果与基线一致」
   这个判据本身不成立——**只能判「不劣于基线 -1」**，并记录跑测日期。

**代价**

- 干活时间：约 2.5 小时
- 收益偏低：100 小时内换 LLM 厂商的概率不高；真换了要重标阈值+重跑评测，
  成本远高于 provider 层本身省下的工夫
- 风险：动 `judge()` 主链路，它是「三层兜底」的中枢，出问题影响全部问答

> **v1.1 修正（重要）**：本节原写「97→96 是因为 `DEEPSEEK_MODEL` 是浮动别名、服务端模型变了」，
> 并据此推出「只能判不劣于基线 -1」。**这个结论是错的，已推翻。**
>
> 2026-11-19 晚实测：同一句、`temperature:0`、绕过缓存、连测 8 次 →
> `0.55 / 0.72 / 0.55 / 0.55 / 0.55 / 0.55 / 0.72 / 0.72`。
> **是单次调用抖动**，且抖的是两个离散值（疑似路由到不同推理实例），不是跨天的模型变化。
>
> **对判据的影响**：在抖动面前，「96 与 97 差 1 分」没有统计意义，设「-1 容差」也是假的严格。
> 正确做法是**多次运行看区间**，而不是给单次结果设容差。
> 这也让选项 B 的收益进一步下降——给一个测不准的东西加抽象层，收益无法验证。

## 4. 我建议：A

理由三条，按重要性排序：

1. **`__TTsProbe` 是已存在的真 bug，必须修。** 三个选项都包含它，无争议。
   不修的后果是 M3 打包后语音在 Android 上完全失效——而语音输出是
   `docs/01 §2.1` 定的「主输出通道」。
2. **TTS 是产品明确要求可切换的那一块**（`docs/01` 要求 M3 离线原生 TTS，
   而 M2 只有浏览器层）。现在 Android 浏览器根本没有 speechSynthesis，
   provider 化的收益是立刻能实测的第二条路。
3. **B 的收益不抵风险。** 换 LLM 厂商后必须重标阈值，而阈值重标又要 100 条评测集，
   而这个基线本身在漂（96/97/98 三次实测）。在没有稳定基线的前提下做 provider 化，
   等于给一个测不准的东西加一层抽象。

**如果你更想省时间**：C 也合理，它至少把真 bug 修了。选 C 的代价写清楚——
TTS 仍然不可切换，且这个债在 M3 会以「Android 没声音」的形式再出现一次。

## 6.5 执行结果（v1.1，2026-11-19）

**选项 A 已落地。以下是实际做了什么，以及与提案的偏差。**

### 6.5.1 实际改了什么

| 文件 | 改动 | 与提案的差异 |
|---|---|---|
| `app/voice.js` | ① 新增 `PROBES` 探测链（tauri→web）与 `ENGINES` 实现表<br>② `detect()` 改为按链探测，抽出 `activate()` / `activateWeb()` / `detectNone()`<br>③ `speak()` / `stop()` 改为查表分发，拆出 `stopTauri()` / `stopWeb()`<br>④ `setTauriAdapter` 补写 `__TTsProbe`<br>⑤ 删掉指向 index.html 的假注释 | 多做了三件事（见 6.5.2） |
| `tools/selftest_m1.mjs` | 604 → **623** 条（新增 §12-d，20 条） | — |

### 6.5.2 比提案多做的三件事（都有理由）

**① `setTauriAdapter` 里加了「重新探测」。**

提案只要求写 `__TTsProbe`。但实际存在时序问题：页面加载时 `detect()` 会先跑，
把 `engine` 定成 `'web'`（或 `'none'`）；宿主在之后才注入适配器。
此时探针虽然写上了，`engine` 却还停在旧值 —— **bug 换个形状继续存在**。
所以补了一句：当前不是 tauri 时，注入后重探一次（只在必要时，避免推翻已正确的状态）。

**② 导出 `engines()` 与 `activeEngine()`。**

提案没提。加的理由：改引擎/排查时不该只能靠读源码。
现在「有哪几个引擎、当前是哪个」可以直接问，断言也能据此写。

**③ 修了一个提案没发现的隐患：`stop()` 的兜底。**

原来 `stop()` 是「tauri 就调宿主，否则调浏览器 cancel」。改成查表后，
若 `engine === 'none'`（没有任何引擎），就没有实现可调 —— 会变成「按了停止什么都不做」。
保留了兜底：没有当前引擎时仍尝试 `speechSynthesis.cancel()` 一次，避免残留合成器继续念。

### 6.5.3 投毒反证（不能只看全绿）

| 投毒 | 变红的断言 |
|---|---|
| A. 删掉 `__TTsProbe` 写入（回到修复前） | **2 条**：「必须写 `__TTsProbe`」「注入后引擎应切到 tauri（实际 web）」 |
| B. 保留写探针但不重探 | **1 条**：「注入后引擎应切到 tauri（实际 web）」 |
| C. `stop()` 不查表 | **3 条**：tauri 时未调宿主、tauri 时误调了浏览器 cancel、web 时 cancel 被调了 2 次 |

> 投毒 A 与 B 红的断言不同，说明两条断言各管一件事：A 卡「探针没写」，B 卡「写了但没生效」。
> 若只留一条，会漏掉另一半。

### 6.5.6 一个观察（值得记）

断言总数会随行为变化：投毒 A 时是 619 条（比正常的 623 少 4 条），
因为部分断言在「引擎是否切到 tauri」的 `if` 分支里，条件不成立就整段跳过。

**这不是缺陷，但要知道**：断言数变少本身也是信号 —— 看到「623 → 619」应当想到
「有分支没进去」，而不是「测试少跑了」。若要做到「跳过也报红」，得改成分支外断言，
但那样会把「引擎本来就是 web」的正常场景误判成失败，所以保持现状。
