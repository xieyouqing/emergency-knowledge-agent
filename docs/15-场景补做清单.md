## 1. 第一批逐项规格

### 1.1 `cpr` — 心肺复苏（成人无呼吸/无脉搏）

| 项 | 要求 |
|---|---|
| 类型 | **新场景**（新建 `knowledge/cpr.json`；`index.json` 新 slot） |
| 覆盖 | **成人 only**；儿童/婴儿、溺水 CPR 不做（另立来源） |
| `life_threatening` | `true` |
| `emergency_number` | `120` |
| 来源 | **中国红十字会官网 CPR 页逐字原文**；必须含 ①按压:通气比 ②先按压还是先通气 ③按压深度/频率（`06` D-2/D-3） |
| 禁止 | `mem.gov.cn` 2018 的 15:1、119 摘要的“先 2~5 次人工呼吸”**不得**作为比例/顺序来源 |
| 结构 | `triage` 必须为空；直接 `steps`，不许先问“能不能动” |
| 步骤 | `immediate` 3–7 条、`next` 1–7 条、`never` ≥1 条；全部逐字来自来源 |
| 路由 | 明确说「没有呼吸 / 心跳停了 / 没有脉搏」→ `cpr`；`fall_elderly` 不得再吃这些词 |
| 验收 | `check_source_quote.py --id cpr` = pass；`validate_knowledge.py` PASS；人工签 `step_order_ok` |
| 测试问法 | 没有呼吸了 / 心跳停了 / 没有脉搏了 / 我妈摔倒了没有呼吸 / 还有呼吸但没反应（后者不走 cpr） |

## 5. 数据交付模板（每个新场景照填）

```json
{
  "schema_version": "1.0",
  "id": "<场景id>",
  "name": "<中文名>",
  "status": "draft",
  "version": "0.1",
  "life_threatening": true,
  "emergency_number": "120",
  "aliases": ["<用户可能说的其他说法>"],
  "keywords": ["<检索词>"],
  "triage": null,
  "steps": {
    "immediate": [{ "text": "<逐字来自来源>" }],
    "next": [{ "text": "<逐字来自来源>" }],
    "never": [{ "text": "<逐字来自来源>" }]
  },
  "daily": {
    "summary": "<一句话>",
    "why": "<原因，逐字可查>",
    "prevention": ["<日常预防>"],
    "misconception": "<常见误区，逐字可查>"
  },
  "source": {
    "name": "<来源名>",
    "url": "<链接>",
    "date": "<获取日期>",
    "quote": "<原文摘录，照抄不转述，≥10 字>"
  },
  "checklist": {
    "source_quote_verbatim": true,
    "step_order_ok": false
  }
}
```

**必须同时交**：

1. 10–20 条测试问法（现场 / 预防 / 否定 / 库外各若干）
2. 场景的 `DANGER_RULES` 建议词（8–12 个；供代码维护，不是数据文件）
3. 人签记录（姓名/日期/“步骤顺序已复核”）

## 13. C10 根因修复（2026-11-21，用户裁决方案 A）

### 13.1 先回答一个技术质疑：「不是还有向量检索吗，分数压不住吗」

**代码里没有向量检索。** 实测 `RETRIEVAL.listEngines()` 返回 `['l3','bm25','hybrid']`：

| 引擎 | 实现 | 默认 |
|---|---|---|
| `l3` | `scoreEntryByRules` 离散打分（alias 10 / name 9 / keyword 4+k / 0） | **是** |
| `bm25` | 字符 bigram（无词典） | 否 |
| `hybrid` | `rrfFuse([l3, bm25])` | 否 |

向量与 cross-encoder 精排只存在于 `docs/03` §3.3 的**设计**（D-2=B：内置 embedding 25–30MB），**代码未实现**。

**且即使实现，L3 这一层也压不住，因为设计上它没有阈值层**（`docs/03` §3.3）：

| 链 | ② 相对筛 | ③ 绝对筛 |
|---|---|---|
| L1（有精排） | `top1-top2 ≥ δ_rerank` | `top1 ≥ τ_rerank` |
| L2（断网+向量） | `top1_rrf-top2_rrf ≥ δ_rrf` | `cosine_top1 ≥ τ_vec` |
| **L3（现状）** | ~~不需要~~ | ~~已并入 ①~~ |

原文理由：「`scoreEntry()` 输出离散值……`top > 0` 本身就是「规则命中」这个明确事实，不是「相似度够不够」的估计。**离散判据不需要再用相对比较兜底。**」

所以 `score=5` 只表示「命中了一个 keyword」，**没有「命中得够不够」这个概念**，`retrieve()` 里也没有最低分门槛。

三引擎实测（`划破了但没出多少血`）：

| 引擎 | 命中 | 分数 |
|---|---|---|
| l3 | severe_bleeding | 5.00（`keyword*1`） |
| bm25 | **无命中** | 0.00 |
| hybrid | severe_bleeding | 0.02（RRF，只有 l3 一路给候选） |
