## 2. 改了什么（6 个文件）

| 文件 | 改动 | 为什么 |
|---|---|---|
| `tools/llm_proxy.mjs` | ① `PORT` 读 `process.env.PORT`（平台注入优先）<br>② `HOST` 检测到注入 `PORT` 时绑 `0.0.0.0`，否则仍绑 `127.0.0.1`<br>③ 新增 `app/` 静态托管，`/` 优先出 `standalone.html`<br>④ 新增额度闸 | 平台只暴露一个端口；页面与 API 必须同源 |

| `app/log.js` | `resolveApiBase()` → `window.API_BASE`；从 URL 读 `sharecode` → `window.API_AUTH` | 端点不再写死；API 自带凭据，不依赖 cookie |
| `app/llm.js` | 端点拼 `API_AUTH`；`actUrl`/`expandUrl` 的 replace 改用 lookahead | 端点带 query 后 `/\/judge$/` 会失配，自主循环会静默打回 /judge |
| `app/asr.js` | 端点拼 `API_AUTH` | 同上 |
| `package.json` | 加 `start`、`build:standalone` | 平台启动入口 / 重新生成单文件 |

### 2.1 为什么必须有单文件版（这一条是踩出来的，不是预防）

部署平台前面有一道**分享码闸**，无凭据请求一律 `403`。凭据只有两条：

1. cookie `__wb_rsc`（`SameSite=None; Secure`）
2. URL 里带 `?sharecode=`

页面里的 `<script src="app.js">` 这类子资源请求**不带 query**，只能靠 cookie。
实测（无 cookie）：

```
GET /app.js              → 403
GET /app.js?sharecode=XX → 200
```

**只要浏览器不给这个第三方 cookie（内嵌预览、拦截第三方 cookie、部分手机浏览器），
全部脚本 403，页面就是白屏。** 这就是 2026-11-21 那次「点进去空白」的根因。

**试过但不可行的方案**：由代理在返回 HTML 时把分享码注入每个 `src`。
实测网关先校验再转发，**转发时把 query 剥掉**，服务端读不到分享码
（证据：`/` 的 `Content-Length` 恒为 5352，与源文件一致，注入未发生）。

**最终方案**：把 CSS 与全部脚本内联进一个 HTML，页面**零子资源请求**；
API 调用由前端从 `location.search` 读分享码自己带上（`app/log.js` 的 `API_AUTH`）。
这样 cookie 完全不需要了。

```bash
node tools/build_standalone.mjs    # 改完 app/*.js 或 index.html 后必须重跑
```

> `app/index.html` 仍是开发源文件，本地 8899 演示与既有测试继续用它；
> `standalone.html` 是生成物，已加入 `.prettierignore`，不要手改。

### 地址判定规则（四场景，已逐条实测）

| 页面所在 | 解析出的 API 地址 |

## 3. 额度闸（新增，防评审期被刷空）

| 闸 | 默认 | 环境变量 |
|---|---|---|
| 单 IP 每分钟 | 40 次 | `LLM_RATE_LIMIT` |
| 全局每日 | 2000 次 | `LLM_DAILY_CAP` |

- **只拦花钱端点**：`/judge` `/act` `/expand` `/asr`。
- 静态页、`/health`、`/log` 不计数 —— 额度耗尽时页面仍能打开，打字走 l3 兜底。
- 被拦返回 `429` + `degraded:true`，前端按既有逻辑回落 l3，不白屏。
- 实测：连发 45 次，第 40 次起 `429`（前序已消耗 1 次，计数准确）。

## 6. 阿里云广州切换路径（备案之后）

**当前不具备条件**：广州属中国内地，域名解析到该机器必须先完成 ICP 备案。
阿里云文档：未备案域名解析到内地节点会被监测系统阻断访问。
初审 1~2 工作日 + 管局 1~20 工作日，**赶不上 11/22 交付与 11/25 评审截止**。

备案通过后按下列步骤切：

```bash
# 1. 装 Node 22（Ubuntu 24.04 apt 自带 18.19.1，上游已 EOL，不建议）
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

# 2. 放代码（不需要 npm install，运行时零第三方依赖）
sudo mkdir -p /opt/anban && cd /opt/anban
# 上传程序包并解压，确认 .env 已配置

# 3. 起服务（只绑回环，由 nginx 对外）
PORT=8787 LLM_PROXY_HOST=127.0.0.1 node tools/llm_proxy.mjs

# 4. nginx 反代 443 → 127.0.0.1:8787，证书用 Let's Encrypt（免费）
```

**推荐 nginx 反代而非直接绑 0.0.0.0**：key 在 node 进程身后，少暴露一层。
