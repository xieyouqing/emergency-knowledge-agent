## 1. 产品定位

**安伴**是一款面向 **45–70 岁中老年人**的**应灾智能助手**，日常称呼为「小安」。

它覆盖两头：

- **日常防灾科普**：怎么预防煤气泄漏、热水器温度设多少、灭火器怎么选
- **灾时强制处置**：着火、煤气泄漏、跌倒、溺水、大出血等现场，直接给可靠步骤并朗读

产品不是通用聊天机器人。它只回答知识库中已审核的应灾与急救内容；库外问题一律拒答，只给拨号按钮。

### 1.1 目标用户

- 主用户：45–70 岁中老年人，重点是**不熟悉智能手机、识字量低、不会拼音**的人群
- 60 岁以上是风险最高的子群，但不是唯一用户
- 次用户：与中老年人同住的家庭成员，负责辅助打开、代为提问

### 1.2 设计约束

- 紧急场景**零文字输入**：按住说话即可
- 字号 ≥ 24pt，点击区 ≥ 48px
- 语音播报是主输出通道，文字是备份
- 刷新即清会话，不把上一个人的紧急状态带给下一个人

## 2. 需求分析

### 2.1 真实痛点

| 痛点 | 现有方案的问题 | 安伴的处理 |
|---|---|---|
| 出事时找不到入口、打不出字 | 通用 App 层级深、输入门槛高 | 首屏只有「按住说话」主按钮 + 4 个高频场景 |
| 通用大模型会编急救步骤 | “看起来合理”比“答不了”更危险 | 模型只选工具，不写步骤；库外零步骤 |
| 老人看不清、听不清 | 小字、快语速、无朗读 | 大字、自动朗读、默认偏慢 |
| 火灾等场景需要先分诊 | 一上来给步骤容易给错 | 先问「自己屋里 / 门外楼道」再出步骤 |
| 中老年人不会一次说全 | 单轮问答断片 | 会话内记忆，只存用户原话 |
| 日常问「怎么预防」被当成现场 | 关键词误判、强行锁紧急 | 日常 / 预案走 `get_daily`，不锁紧急 |

### 2.2 产品边界

- 不做通用聊天
- 不做自动拨号（只生成按钮，由用户按下）
- 不做账号体系、不做跨会话画像
- 不做医学诊断；只做公开科普整理
- 不具备的急症（如儿科 CPR、未收录场景）直接拨号，不编步骤

## 3. 功能架构

### 3.1 双模式

| 模式 | 触发 | 输出 | 是否锁紧急 |
|---|---|---|---|
| 日常 | 预防、知识、参数、选购边界 | 日常科普卡 | 否 |
| 紧急 | 用户报告正在发生的危险 | 分诊卡 / 步骤卡 / 拨号卡 | 是（S8） |

日常与紧急由判定层区分，不靠单个关键词硬切。

### 3.2 主流程

```
用户按住说话 / 打字 / 点场景
        ↓
ASR（云）或文字
        ↓
/act 自主循环
  ├─ 模型选工具（9 个）
  ├─ 代码前置门校验
  ├─ 执行工具
  └─ 结果回灌，继续或结束
        ↓
渲染：分诊卡 / 步骤卡 / 日常卡 / 拨号卡 / 拒答卡
        ↓
自动朗读（内容全读，不读界面批注）
```

### 3.3 16 个知识场景

燃气泄漏、家庭火灾、一氧化碳中毒、老人跌倒、烧烫伤、触电、电器起火、气道梗阻、溺水、地震、电梯困人、大出血、心肺复苏、卒中、中暑、食物中毒。

每条包含：来源、逐字摘录、人工签步骤顺序、分诊、步骤、禁忌、日常字段。

### 3.4 9 个工具

`lookup_scene` / `get_steps` / `get_daily` / `triage` / `speak` / `dial` / `refuse` / `ack` / `ask`

- 出内容前必须 `lookup_scene` 且 `found=true`
- `dial` 只生成按钮，不代为拨出
- 用户明确说「帮我打119」时，`dial` 带 `requested` 标志，只出拨号卡，不锁紧急
- 同一句里还有现场危险时，按现场优先

### 3.5 会话记忆

- 只存用户原话，不存模型结论
- 仅内存，刷新/关闭即清
- 代理侧 `context` 分区注入，前端不拼接
- 用户说「不是这个 / 另一个人 / 换个问题」立即清空
- `evidence` 必须落在当前句：只引用上文、且当前句不是纯追问 → 拒答

## 4. 技术说明

### 4.1 技术栈

| 层 | 选型 | 原因 |
|---|---|---|
| 前端 | 原生 HTML/CSS/JS，无构建 | 评审可直接打开、复现成本低 |
| 本地/云端代理 | Node.js（内置模块） | 持有 API key，前端拿不到 |
| 模型 | DeepSeek API | 中文语义判定与工具选择 |
| 反向代理 | Nginx | 同域静态页 + `/judge` `/act` `/asr` |
| 部署 | Ubuntu + systemd + certbot | 香港/境外机器可免 ICP |

### 4.2 关键设计：把生成关进笼子

1. **模型不写步骤**：只输出 `act + args + turn + evidence`
2. **前置条件门**：出内容前必须查库且 found
3. **安全闸**：S1 不编、S5 拨号、S7 日常动作来源、S8 紧急锁定、S10 来源机器比对、S11 人签步骤顺序
4. **数据闸**：来源逐字 `quote` + 人工签 `step_order_ok`
5. **证据闸**：`evidence` 不落当前句 → 拒答，防止上文污染
6. **范围闸**：儿科 CPR / 儿科溺水 → 拨号；溺水走 `drowning`，不套成人 CPR

### 4.3 三层兜底

| 层 | 条件 | 行为 |
|---|---|---|
| `/act` | 正常 | 模型自主选工具，多步循环 |
| `/judge` | `/act` 不可用 | 单次判定，代码映射动作 |
| `l3` 字符检索 | 模型不可用 / 断网 | alias/name/keyword 离散分，top=0 即拒答；不白屏 |

检索层当前是 `l3` / BM25 / hybrid（字符+BM25），**不是向量检索**；向量与精排留到 M3 离线态评估。

### 4.4 数据与来源

- 16/16 条目来源重跑 `pass`（`tools/check_source_quote.py`）
- 机器比对只判字面一致，**不判医学正确**；步骤顺序必须人签
- 溺水条目：中国红十字会《暑期防淹溺》+ 漳州市红十字会补强
- 烧烫伤水温：全国 12320 管理中心补强

### 4.5 部署

- 同一域名：Nginx 静态页 + 反代 Node 8787
- HTTPS 必须：手机麦克风需要安全上下文
- 模板：`../../deploy/nginx.anban.conf`、`../../deploy/nginx-tunnel.conf`、`../../deploy/anban-proxy.service`
- 详细步骤：`../../deploy/DEPLOY.md`

## 5. 使用说明

### 5.1 本地演示

```bash
cp .env.example .env
# 填 DEEPSEEK_API_KEY
node tools/llm_proxy.mjs
cd app && python -m http.server 8899
# 打开 http://localhost:8899/index.html
```

Windows 可直接双击 `start-demo.bat`。

### 5.2 线上访问

- 香港/境外 Ubuntu：按 `../../deploy/DEPLOY.md`
- 域名 + HTTPS；手机麦克风必须 HTTPS
- Android 浏览器没有 `speechSynthesis`：朗读需桌面浏览器；Android 原生 TTS 属 M3

### 5.3 演示路径

1. 「怎么预防煤气泄漏」→ 日常科普卡 + 朗读
2. 「煤气漏了」→ 步骤卡 + 119 + 朗读「同时拨打 119」
3. 「着火了」→ 先分诊「自己屋里 / 门外楼道」
4. 「我妈摔了」→「她还有呼吸但没反应」→ 拨 120
5. 「帮我打119」→ 拨号卡，不锁紧急
6. 「电梯广告怎么投诉」→ 拒答 + 120

## 7. 安全与隐私

- API key 只在服务端 `.env`，前端不可见
- 会话记忆不落盘，刷新即清
- `localStorage` 只存语音开关，不存对话
- 运行日志在服务器 `logs/`，保留 7 天，含截断后的用户文本
- 代理有单 IP 限流与每日总量上限
- 不自动拨号、不自动诊断、不生成库外步骤
